# 组合策略：回测、核验与审批工作流

更新：2026-11-18。入口：投资判断 → 组合策略。仍为本机插件：不连接券商、不写真实账本、不自动生成订单。

## 1. 多资产历史再平衡（纸面）

输入由你或 Agent 显式提供：`baseCurrency`、`initialCash`、`cashTargetWeight`、2–20 项资产（`adjustment:"raw"`、`lotSize`、日线 open/close、公司行动、费用税表）、逐期 FX、再平衡频率与日期区间。

- 共同交易日交集；前一日收盘形成目标，下一共同交易日开盘执行；先卖后买、整手、现金不为负。
- 分红：除息日按持仓形成**应收**，支付日才入现金并扣税；拆股按比例调整数量、不产生收益。
- 费用税表必须显式提供（缺表即拒绝，不默认 0）。`minFee` 为资产币种每单。
- 同日混合拆股/分红、同日多次拆股等未定义顺序会被拒绝。
- 跨币种使用**过去**汇率（≤7 天），不未来填充。

**口径限制**：即使输入声明 `actionsComplete` 与税表齐全，也只是「输入声明完整」；系统未对外部数据做真实性核验，因此 `coverage.totalReturnClaim` 永远为 false，`completeAccounting` 只代表输入覆盖声明。除权价格跳变、送转、股改等复杂行动未建模时不得称完整总回报。

## 2. 资产与数据核验

「本次允许只读导入持仓」勾选后才会读取本机持仓与行情；勾选是一次性的，执行后自动清除。

- 价格、汇率（Frankfurter 公开参考中间价，非可成交价）、基金披露分别校验来源时点；价格/汇率 >7 天、基金披露 >120 天视为过期。
- 外币缺汇率 → 该项未知；**不按 0，也不把已知部分归一化冒充全组合**。不完整时结果不返回整体权重与币种暴露。
- 基金穿透只用披露的前 N 大重仓：显示已知部分与未覆盖残差，不与基金本身重复相加。
- 协方差仅在同币种、共同日期、≥30 个日收益上计算（样本 n−1，年化 252）；跨币种拒绝、不把多日收益当单日。
- 导入不猜账户现金，也不用成本价替代市价。

## 3. 版本库与审批状态机

保存于 `data/portfolio-strategy/portfolio-strategies.json`（独立于持仓与账本）。

- 每次保存生成**新版本**，旧版本不可改写；`parentId` 建立谱系。
- 状态流转：`draft → review → approved | rejected`，`approved → retired`；驳回/退役需新建版本。并发写入用乐观版本号（CAS）。
- 批准仅允许 `actor=user`，且必须：策略评估非 `BLOCKED`、存在纸面权重方案、审阅快照 hash 一致。
- 服务端额外要求：批准时策略 `asOf` 距今 **≤7 天**，否则必须用今日行情与证据保存新版本。历史快照不能当当前核验。
- 批准含义仅为「允许纸面跟踪」，不授权交易、不改账本，界面会二次确认并明确这一点。
- 文件损坏、JSON 语法错误不会被静默修复或覆盖，会抛错上报。

## 4. 工具与接口

| 用途 | 工具 / 路由 |
| --- | --- |
| 组合权重与约束检查 | `portfolio_strategy_review` |
| 多资产纸面回测 | `portfolio_backtest_run`；`POST /strategy/backtest` |
| 估值/穿透/协方差核验 | `portfolio_data_verify`；`POST /strategy/verify` |
| 只读导入持仓与行情 | `POST /strategy/import`（需 `authorized:true`） |
| 版本列表/保存 | `GET|POST /strategy/versions` |
| 状态流转 | `POST /strategy/transition`（需 `userConfirmed:true`） |

## 5. 未实现与不能宣称

- 自动获取完整基金持仓（仅公开前 N 大）、自动公司行动库、真实税费规则（按账户/地区定制）；
- 交易撮合、盘口深度、涨跌停排队与流动性冲击建模；
- 多用户/多进程文件锁（当前为单进程串行）；
- 浏览器交互与窄屏视觉验收（本轮未执行）。
