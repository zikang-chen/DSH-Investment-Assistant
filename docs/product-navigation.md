# 产品信息架构与页面跳转（2026-11-17）

## 设计目标

围绕「选标的→查资料/走势→发起研究→保存判断→复盘」组织，不按后端模块数量堆页面。不删除原工具、数据或金融计算，不把评分等同能力。

## 五个一级入口

| 一级入口 | 二级页面 | 职责 |
|---|---|---|
| 总览 | 工作台、证据待办 | 市场摘要、持仓/自选概况、最近政策、复核与补证入口，不嵌整套个人档案 |
| 投资判断 | 研究判断、组合策略、档案与复盘 | 结构化研究、原判断与反证；个人研究档案、周复盘、人工确认 |
| 市场研究 | 行情、宏观、政策、新闻、证券档案、筛选发现、基金研究、机构追踪、资料库 | 市场与标的的研究材料，不将基金研究/机构持仓误归个人资产 |
| 我的资本 | 持仓与自选、账户与收益、规划与目标、金融学习 | 个人资产与规划；成长内容归规划，不在总览展示“综合0·启蒙” |
| 设置 | 数据源、技能、接口 | 配置、连通性与诊断，不作为日常研究起点 |

## 总览内容

- 研究问题入口与流程快捷键。
- 本地资本/政策资料/证据待办/观点复核摘要，标签明确数据性质。
- 市场速览使用现有指数快照；未取得时显示缺失，不用政策数量代替行情。
- 我的组合展示持仓、自选数量和账户收益入口，不合并未知汇率资产。
- 最近入库政策标为入库资料，不伪称全网最新动态。
- 档案与复盘不再整套叠加到总览；单独放投资判断下面。

## 规划与学习

财务规划/学习移至「我的资本→规划与目标」，默认折叠明细。取消成长综合分和“启蒙”等级展示，保留原记录、课程进度、诊断建议、对话执行与复盘能力。评分数据不删除，但不拿0分评价用户。

## 上下文与返回

- 总览“查看最近判断”传adviceId，避免打开以前选中过的另一条。
- 基金研究/发现/持仓→证券档案保留原入口。
- 证券档案→K线保留code/name/type/market/secid，挂载后自动滚动到对应图表，不只切到行情页顶部。
- 日股等海外证券保持secid，走全球K线路径，不误送国内历史接口；同码不同市场的档案组件身份也区分。
- “返回证券档案”恢复本次跳转来源证券，且不覆盖原基金/发现等入口；在行情页主动改选其他标的会清理旧返回提示。
- 公司概况使用双列自动换行，嵌套信息逐字段展开、元数据单列，不把对象压成巨型JSON单元格；基金净值采样保留最新点。
- 数据源有草稿时必须确认离开；取消则不更新证券目标、不打开分析、不发跳转锚点。
- 证券事件监听读取最新dirty状态，避免闭包绕过确认。
- 原`home`的growth锚点兼容到wealth，journal/reviews/approvals兼容到journal。

## 不变的安全边界

持仓修改仍须确认；组合授权默认关闭；对话投递与实际保存不同；未知行情/汇率不生成虚假收益。未修改账本、研究原文、学习记录或资产数据。

## 验证与限制

`npm run test:product-navigation`检查入口分工、规划归位、守卫、返回上下文、观点聚焦与旧锚点。另跑build、UI/证券/资本契约与8类金融回归。

本轮未连接真实浏览器进行多宽度交互/视觉验收；静态测试不能证明所有显示细节。页面切换仍会卸载多数子页面，部分搜索/筛选表单未做到全局持久化，不将其描述为完整浏览器路由栈。
