# 数值元信息与关键数据缺口

结论先写：这轮最影响判断的不是"少一个源"，而是**数值没有元信息**——同一个 73.9，不知道单位、时点、窗口、来源，就无法引用进结论。

## 一、约定：每个可引用数值都带元信息

```json
{
  "value": 73.9,
  "unit": "%",
  "asOf": "2026-11-24",
  "window": "5y",
  "source": "东方财富 · 估值分位",
  "stale": "fresh",
  "conflict": false
}
```

字段含义：

| 字段 | 取值 | 为什么必须有 |
| --- | --- | --- |
| `unit` | `%` / `CNY` / `根` / 指数点 | 资金流 `mainNetInflow` 是元还是万元，决定量级判断 |
| `asOf` | `YYYY-MM-DD`（可含时间）或 `null` | 缺时点就用抓取时间顶替，等于把旧值当新值 |
| `window` | `5y` / `20d` / `当日` | "PE 分位 73.9%" 是 3 年还是 10 年分位，结论可能相反 |
| `source` | 具体来源 | 口径争议时要能回溯 |
| `stale` | `fresh` / `t1` / `t2` / `stale` / `unknown` | T+1 净值与盘中价混用会算出假溢价 |
| `conflict` | `true` / `false` | 两个独立来源不一致时必须显式标记，不能挑一个引用 |

实现：`src/data/metric.ts` 提供 `metric()`、`staleness()`、`conflictOf()`、`sessionOf()`。规则是**缺就 null、不补 0、不拿抓取时间冒充数据时点**。

## 二·补：正文质量闸门

政策采集在入库前检查提取后的正文：**少于 300 字**，或 `ICP备 / 网站标识码 / 版权所有 / 主办单位` 合计 **出现≥2次**，返回 `parse_failed`，不分配政策id、不保存为有效正文、不镜像资料库。重复同一标记也计次；不把正常文章外层页脚当成正文拒绝信号。

原因：列表页/页脚的样板文字会被抽取成「正文」，一旦入库就长期占着一个 id，还会被当成证据引用。

## 三、两个低成本的判定辅助

- **交易时段标记**：`get_market_session` 返回 `pre/am/lunch/pm/closed` 与是否完整交易日，并显式声明未接节假日日历——用来避免把半日盘当全天。
- **历史覆盖度**：`get_history_coverage` 返回根数、覆盖区间、≥15 个工作日的疑似缺口、事件缺失数。缺口按工作日估算，不声称是确定缺失。

## 四、验证

`npm run test:metric`：7 组，覆盖新鲜度分级、冲突容差、时段判断（含时区换算）、提前收市白名单、财政部 CSV 解析（N/A 不当 0）、以及"工具不写持久状态"。

未验证：上游可达性会变（东财间歇性重置），上述"已解决"指的是代码路径接通并实测过一次，不是持续可用承诺。
