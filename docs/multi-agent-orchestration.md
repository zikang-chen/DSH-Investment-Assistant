# 研究小组分工


编排形态参考了 Anthropic 的 orchestrator–worker 研究系统、OpenAI Agents SDK 的 handoff 契约、CrewAI 的顺序流程，以及同生态 dsh-trading 的 master + 研究员/交易员/风控预设。共同点只有三条：**一个负责人、明确交接物、执行权集中**。

一条边界：编排只落在研究侧。参考了 Anthropic 的 orchestrator–worker 研究系统、OpenAI Agents SDK 的 handoff 契约、CrewAI 的顺序流程与同生态 dsh-trading 的 master + 三预设；共同点是**一个负责人、明确交接物、执行权集中**。

## 一、边界

我们没有券商通道，也不打算有。所以编排只落在研究侧：

- 主 Agent 仍是唯一收口人；
- 三个角色**只产文本**：事实 / 情景 / 反证；
- 任何角色都不能写账本、不能改策略、不能下单；
- 子代理并行由主 Agent 自己决定，插件不替它调度。

## 二、落地形态

### 工具：`team_brief`

```json
{ "target": "510300", "question": "现在能不能加仓？", "roles": "researcher,risk" }
```

返回三份简报（目标、交回字段、边界）+ 交接顺序 + 汇总规则 + 一段可直接投递的提示词。纯函数，无 I/O。

### 面板：上下文条「相关 → 团队分工」

一键把上述提示词投递到当前对话，由主 Agent 决定是否真的并行委派。**不自动执行**，也不假装已经跑过。

## 三、角色与交回物

| 角色 | 目标 | 必须交回 | 边界 |
| --- | --- | --- | --- |
| 研究员 | 这只标的是什么、现在什么位置、有哪些可核验事实 | 身份与市场；带来源与日期的关键数据；支持证据；反对证据；仍缺的资料 | 不给买卖建议；取不到就写缺失 |
| 交易员 | 在事实上写条件化情景 | 情景与触发条件；动作与规模；失效条件；复核日期 | 只写纸面方案；必须引用事实与日期 |
| 风控 | 主动找反证 | 主要风险；集中度/相关性影响；失效条件是否可观测；需补证据 | 只读；不改持仓；不替用户决定 |

汇总规则写明：事实以研究员为准，情景以交易员为准，失效条件以风控为准，**冲突处直接写冲突**，不许合并成一句。

## 四、为什么不做更多

- **不做自动并行**：插件替 Agent 决定并发度，会让成本与失败面失控（Anthropic 也提到同步执行的瓶颈与 token 成本）。
- **不做角色人格**：角色边界写成交回字段与禁止项，比写成性格描述更可验证。
- **不做执行型 agent**：没有合规通道，任何“自动下单”都是假能力。

## 五、验证与遗留

- `npm run test:team-plan`：8 组离线用例（角色边界、缺标的报错、授权默认关闭、提示词包含顺序与「不生成订单」、无 I/O、接线只有一个按钮且不自动执行）。
- 未验证：宿主里子代理实际并行效果、token 成本、真实多轮交接质量。这些需要在有模型配额的环境跑真实任务，不能用离线测试代替。
- 后续若要做状态机编排（多轮、可中断、可恢复），再考虑引入 supervisor 形态；当前顺序编排已覆盖投研主路径。

## 六、相关：回测输入构造器

多资产回测原先要手写整段 JSON（每资产含逐日价格、税表、公司行动），实际没人会这样填。新增
`src/client/backtest-builder.tsx`：填资产与权重 → 从本地历史取价 → 生成输入 → 直接跑纸面回测。

口径保持诚实：

- 价格取本地历史原始收盘（不除权），跨除权日会跳空，界面明确标注；
- 税表由用户填，标注「未逐项核验」；
- 公司行动为空时 `actionsComplete=false`，后端据此只给部分口径，不声称完整总回报；
- 跨币种直接拒绝并提示先补汇率，不静默按 1:1 处理。

`npm run test:backtest-builder`：7 组（区间裁剪、权重与现金合计、跨币种拒绝、历史不足拒绝、
参数逐项报错、模块只读、接线）。
